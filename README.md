# 그린노트 (Green Note)

기기에만 저장되는 골프 스코어 관리 앱 (PWA). 서버·계정·광고 없이 동작하고, 데이터는 브라우저의 IndexedDB에 저장됩니다.

## 실행

```bash
node server.mjs        # http://localhost:5173  (Windows: start.bat 더블클릭)
```

같은 Wi‑Fi의 폰에서는 서버 실행 시 출력되는 `http://<PC IP>:5173` 주소로 접속할 수 있습니다.

## 폰에 앱처럼 설치하려면

홈 화면 설치와 오프라인 동작(Service Worker)은 **HTTPS** 주소에서만 됩니다. 이 폴더를 그대로 정적 호스팅에 올리면 됩니다.

- GitHub Pages / Cloudflare Pages / Netlify 에 폴더 전체 업로드 (빌드 과정 없음)
- 접속 후 Android Chrome: 메뉴 → *홈 화면에 추가*, iPhone Safari: 공유 → *홈 화면에 추가*

## 기능

| 요구사항 | 구현 |
|---|---|
| 라운딩 일자·코스·시간·날씨 | 정보 탭 (날씨 6종 + 기온). 코스는 저장돼 다음부터 자동완성, 홀별 파도 함께 불러옴 |
| 9홀 코스(전반/후반) 이름 | 골프장 안의 9홀 코스(서·남·동 등)를 **전반/후반 이름**으로 입력. 저장된 이름을 고르면 그 코스의 파가 채워지고, 대시보드에서 **코스별 평균**과 **코스별 홀 히트맵**으로 분석 |
| 코스 검색 | 코스 이름 입력 후 **검색** → 내 코스 + OpenStreetMap 검색 결과 목록에서 선택, 27홀 이상이면 전/후반 9홀 선택. 못 찾으면 웹 검색 링크 · 붙여넣기 입력 |
| 홀별 스코어 · 퍼팅 · OB · 해저드 | 홀별 입력 탭. 버디/파/보기 빠른 버튼, ± 스테퍼, 9홀/18홀. **퍼팅은 스코어를 입력하면 기본 2로 채워지고** 퍼팅·OB·해저드는 언제든 수정 (저장한 기록은 상세 화면에서 홀 번호를 눌러 수정) |
| 분석 대시보드 | 평균 타수 옆 **추정 핸디캡**(WHS 방식 간이 계산), 평균·베스트·추세, 인사이트, 스코어 분포, 파 타입별, 퍼팅(3퍼트·그린적중), OB/해저드, 전/후반, 날씨별, 코스별, **홀별 평균 스코어(저장된 코스를 드롭다운으로 골라 코스별 히트맵 · 파 대비/평균 타수 전환 · 어려운 홀 TOP3)** |
| 스코어카드 이미지 자동 적용 | 기기 안 OCR(Tesseract.js, 한글+영문). 코스명 · 날짜 · 시간 · 홀별 파 · **내 이름 줄의 스코어**를 읽어 확인·수정 후 적용 |
| 기기 저장 | IndexedDB. 설정에서 JSON 백업/복원 |

## 스코어카드 인식 사용 요령

- 표가 화면에 꽉 차게, 정면에서 밝게 촬영하세요.
- 인식 결과는 바로 저장되지 않고 **확인·수정 화면**에서 각 줄의 용도(파/내 스코어/퍼팅)와 숫자를 고친 뒤 적용합니다.
- 여러 명이 적힌 카드는 **내 줄만** “내 스코어”로 지정하세요.
- 인식 엔진과 영어 언어 데이터는 `vendor/tesseract/`에 포함돼 있어 인터넷 없이 동작합니다. 사진은 기기 밖으로 나가지 않습니다.
- **스마트스코어 같은 앱의 결과 화면**(파 대비 점수 0/1/-1 표기, 서/남 두 9홀이 한 줄)을 지원합니다. 합계 칸과 대조해 읽은 숫자가 맞는지 확인해 줍니다.
- 이름이 한두 글자 틀리게 읽혀도(`정경와` 등) 자모 단위로 비교해 찾고, 못 찾으면 이름 칸만 크게 잘라 **다시 읽습니다**. 그래도 못 찾으면 첫 번째 줄을 임시로 고르고, 맞는 줄에서 **내 줄로 선택**을 누르면 그 이름 표기와 줄 순서를 기억해 다음부터 자동으로 고릅니다.
- 설정(또는 스캔 화면)에 **내 이름**을 저장해 두면 여러 명이 적힌 카드에서 내 줄만 자동으로 고릅니다. 이름 일부가 `김**`처럼 가려져 있어도 앞부분이 같으면 찾습니다.
- 숫자를 잘못 읽은 경우: 카드 전체가 파 대비 형식이면 모든 표를 같은 형식으로 보고, 한 9홀에서 상식 밖의 값(예: 파 대비 `17`)이 **딱 한 칸**이면 카드의 합계 칸으로 그 값을 복원해 표시합니다(복원한 칸은 강조). 두 칸 이상이면 빈 칸으로 두고 직접 입력하게 합니다.
- **내 이름을 찾으면 다른 플레이어 줄은 결과에서 제외**하고, 내 줄과 파 줄만 보여줍니다. 이름을 못 찾았을 때만 후보 줄을 모두 보여줘 직접 고르게 합니다.
- **`동-서`처럼 하이픈으로 이어진 코스 표기는 전반 `동` · 후반 `서`로 나눕니다.** `화성상록 동-서`, `화성상록(동-서)`, OCR이 하이픈을 `ㅡ` `—` `~` 등으로 읽은 경우도 인식하고, 확인 화면과 라운드 입력 화면에서 `동-서`라고 직접 써도 나눠집니다. 골프장 이름과 붙어 있어 경계를 알 수 없는 경우(`화성상록동-서`)는 나누지 않습니다.

## 추정 핸디캡

평균 타수 옆에 표시됩니다. WHS(세계 핸디캡 시스템)의 산정 방식을 **파 기준으로 간이 계산**합니다.

- 대상: 모든 홀을 입력한 **18홀 라운드의 최근 20개** (9홀·미완료 라운드 제외, 위쪽 기간/코스 필터와 무관)
- 계산: 각 라운드의 (스코어 − 파) 중 좋은 쪽 N개의 평균 (WHS 표: 3~5개 → 최저 1개, 6개 → 최저 2개−1.0, 7~8개 → 2개, … 20개 → 최저 8개). 3라운드 미만이면 계산하지 않고 진행 상황(예: 18홀 2/3회)을 보여줍니다.
- 한계: 코스 레이팅·슬로프와 홀별 스코어 상한(ESC)을 반영하지 않으므로 공식 핸디캡과 차이가 날 수 있습니다. 값이 0보다 작으면 `+2.1`처럼 표기합니다.
- 구현: `js/stats.js`의 `estimateHandicap`

## 코스 검색 (홀별 파 가져오기)

- 데이터 출처는 **OpenStreetMap**(Nominatim 검색 + Overpass 홀 데이터)입니다. 등록·입력된 골프장만 찾을 수 있고, 홀별 파가 입력돼 있지 않은 곳도 있습니다.
- 못 찾는 경우: ① 스코어카드 사진을 불러오면 파도 함께 읽고, ② 웹에서 파 표를 복사해 **붙여넣기**로 입력하거나, ③ 직접 입력하면 됩니다. 한 번 저장한 코스는 다음부터 내 코스로 바로 불러옵니다.
- Overpass 서버가 바쁠 때는 10~20초 걸리거나 실패할 수 있습니다. 여러 미러 서버에 자동으로 재시도합니다.
- 프라이버시: 검색할 때 **입력한 코스 이름만** OpenStreetMap 서버로 전송됩니다. 라운드 기록과 사진은 전송되지 않습니다.
- 구현: `js/coursesearch.js`(검색·파싱), `js/views/coursepicker.js`(선택 화면)
